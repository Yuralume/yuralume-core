# Update 2026.07.26

1. When several people share one deployment, weather and holidays are finally each their own: previously every character followed the location the site owner had set — same rain, same long weekend. Now each character uses the location its own owner configured. When two players' characters meet, the scene uses one side's location as the single reference (the same side that already decides the encounter's language and time), so a shared scene never has two kinds of weather. Accounts with no location set still fall back to the deployment default, so a single-person install feels exactly as before.
2. News sources can be tagged with a content region: once the admin tags an RSS source with a region, only players living in that region receive topics from it; untagged sources count as global and reach everyone. Players who haven't set a country get no filtering at all, and media that are read across borders are best left global.
3. A character triggered from two places at once no longer does the same thing twice: story progression, the daily story and memory consolidation could previously start twice within moments of each other (for example, messaging from the web and a messaging app at the same time). Now only one runs, the other is turned away and retried later — and a character can no longer end up running two main storylines at once.
4. When an external messaging app redelivers the same message, the character no longer replies twice: receipts are now recorded in the database, so retries and redeliveries are recognized as "already seen." If the character happens to be replying to something else, the system asks the platform to try again shortly instead of swallowing the message.
