判斷原則（預設保守）：
- 若沒有明確證據，優先保持 active。
- 只有在對話明顯顯示目標已達成時才給 done。
- 只有使用者清楚拒絕、或目標已過時才給 abandoned。
- paused 用於暫時擱置、之後可能再接續的情境。

收斂規則（優先於上面的保守原則，符合條件就必須執行）：
1.【近重複必須合併】指涉同一件事的目標必須收成一條：保留敘述最完整、最具體的那條維持 active，其餘全部給 abandoned，並在 notes 寫明併入哪一條。用字不同但講同一件事也算重複（例如「早晨醒來時…」與「清晨醒來時…」、「陪使用者練吉他」與「陪使用者準備吉他發表」若實質是同一件事）。合併時不要新開一條目標來取代它們——直接留下既有那條。
2.【過期必須關門】目標若綁定具體日期或一次性事件，而該日期／事件依上方「今天」已經過去：已完成寫 done，沒成行或已無意義寫 abandoned；兩者都要在 notes 說明是哪個日期／事件已經過去。已過期的目標一律不得留在 active——「明早一起出門」這種寫死相對詞的目標，請照上方日期換算錨點推回它原本指的那一天再判斷。
3.【active 軟上限 ${active_goal_soft_cap} 條】active 目標數量若已達到或超過上限：本次 new_goals 必須是空陣列 []，不得新增任何目標；並且必須先用規則 1、2 把數量壓到上限以下。若合併與過期都用盡仍超過上限，再把優先度最低、最久沒有推進的目標改成 paused（之後可能再接續）或 abandoned（已不重要）。

輸出規則：
- 只輸出一個 JSON 物件，不要任何前言或 code fence。
- 物件包含兩個欄位：verdicts 與 new_goals。

verdicts 欄位：
- JSON 陣列，每個元素包含 id, status, notes。
- id 必須出自上方目標清單（若不在清單中，該項會被忽略）。
- status 必須是以下其中之一：${status_hint}。
- notes 是不超過一句話、描述判斷理由；此欄位玩家可見，必須使用上方指定的玩家可見輸出語言；可選，但套用規則 1、2、3 而改狀態時必填。
- 若某目標沒有變化，省略該目標即可（不要重複列出）。

new_goals 欄位：
- JSON 陣列，每個元素包含 content, priority, tags。
- content 是一句話描述角色接下來想推進的事（第一人稱或目標式）；此欄位玩家可見，必須使用上方指定的玩家可見輸出語言。
- content 若牽涉具體時點，必須寫絕對日期：照上方日期換算錨點寫成「2026-08-02（星期日）早上」，或「明天（2026-08-02）」這種相對詞＋絕對日期雙寫。禁止只寫「明天／明早／後天／這週末」——這段文字會被長期保存，幾天後再讀就會指向錯誤的日子。
- priority 是 1-5 的整數，3 為預設，5 最重要。
- tags 是最多 5 個小寫標籤。
- 最多 ${max_new_goals} 筆；若沒有必要的新目標，給空陣列 []。active 已達軟上限時一律給 []。

範例輸出：
{"verdicts": [{"id": "abc-123", "status": "done", "notes": "使用者已完成吉他社發表"}, {"id": "abc-124", "status": "abandoned", "notes": "與「陪使用者準備發表曲目」重複，已併入該目標"}], "new_goals": [{"content": "陪使用者準備 2026-08-02（星期日）的下次發表曲目", "priority": 3, "tags": ["music"]}]}
